# Kairos Market Lab

**Standalone, public, fully synthetic market simulator — v0.4 fees/FIFO/lifecycle + v0.3 wallets + v0.2 interactive UI + v0.1 LQ-001.** No connection to Kairos AGI runtime, exchanges, real money, real market data, external AI APIs or credentials.

## О проекте

Это автономная лаборатория для исследования механики рынка. Цены **возникают из исполнения виртуальных заявок** в локальном лимитном стакане. Это не генератор готовых свечей и не торговый бот.

**Первый воспроизводимый эксперимент — LQ-001: sudden bid-liquidity withdrawal.** Мы запускаем два искусственных рынка на **одной и той же ленте событий**. В контрольном случае продажи исполняются по исходной ликвидности; в экспериментальном случае непосредственно перед одинаковой агрессивной продажей отменяем 85% заявленного BUY-объёма на восьми верхних ценовых уровнях. Затем сравниваем VWAP, проскальзывание, исполненный объём и глубину стакана.

Все участники, инструменты (`VCOIN/VCU`), балансы и котировки синтетические. Результат не является прогнозом настоящего рынка.

## v0.4 — комиссии, PnL и жизненный цикл

В **интерактивной модели** (`python -m market_lab.web --port 8765`) добавлены:

- Комиссии `maker_fee_bps=10`, `taker_fee_bps=20` по умолчанию, округляемые **вверх для каждой целой монеты** в 0.1-VCU тиках. В небольшом диапазоне цен фактический процент комиссии может отличаться от номинальных bps. Все комиссии поступают отдельному виртуальному участнику `EXCHANGE`.
- Реализованный PnL по FIFO (прибыль/убыток после продажи) и нереализованный PnL по оставшимся виртуальным монетам. Комиссии входят в себестоимость покупки или уменьшают выручку продажи.
- Остановки `STOPPED` после ряда подряд недофинансированных попыток и `BANKRUPT`, когда оценочная стоимость капитала упала до настроенного процента стартовой. Это **условные статусы в spot-симуляции без долгов или принудительных продаж**: остатки сохраняются, открытые заявки отменяются с возвратом резервов.
- Осторожное поведение маркетмейкеров после искусственного шока: часть новых котировок пропускается, остальные выставляются дальше от цены и меньшим объёмом. Это модельное допущение, а не обученная характеристика биржи.
- Статистика доходных/убыточных кошельков по mark-to-market, фактически участвовавших в сделках, остановленных и «банкротных», собранных комиссий и PnL.

Изменять все пять параметров v0.4 можно в локальном интерфейсе с перезапуском синтетического опыта. Все состояния сохраняются **только в оперативной памяти**. Старый CLI LQ-001 остаётся неизменным и без комиссий; две методики нужно различать.

**Проверка:** `py -3.12 -m unittest discover -s tests -v` на Windows.
Всё происходит только внутри `VCOIN/VCU`, без Kairos AGI и настоящих бирж.

## v0.3 — виртуальная экономика участников

Продолжение интерактивной v0.2 **без внешних сервисов**. В памяти создаются
1000 кошельков агентов и два служебных участника (`MAKER`, `STRESS`).
У каждого — целочисленные виртуальные деньги **VCU** и монеты **VCOIN**;
пассивные заявки блокируют соответствующие деньги или монеты. Покупатель
не может потратить больше свободного остатка, продавец — продать больше
свободных монет. Исполненные сделки меняют балансы **обоих** участников,
а отменённые заявки освобождают зарезервированное имущество.

На новой панели видно количество кошельков, исполненные сделки,
отклонённые заявки, суммарную оценочную прибыль и таблицы лидеров.
При каждом тике проверяются отсутствие отрицательных балансов,
сохранение общего количества денег и монет и точное равенство резервов
с размещёнными заявками. Это **не банк**, **не real-market model**,
не бухгалтерия реальных денег, и симулятор не может подключиться
к Kairos AGI или настоящей бирже.

**Ограничения:** комиссии, банкротства, плечо, сложные портфели,
реализованная прибыль и постоянное хранение ledger пока отсутствуют.
Совокупный marked-to-market PnL может быть положительным или отрицательным
при переоценке неизменного количества монет; это не нарушение сохранения
активов и не доказательство полезности стратегии.

## v0.2 — интерактивная синтетическая биржа

Запустить локальный браузерный симулятор (только loopback `127.0.0.1`):

```bash
python -m market_lab.web --port 8765
```

Открыть **http://127.0.0.1:8765/**. На Windows: `py -3.12 -m market_lab.web`.
Стандартная библиотека Python, сторонних зависимостей нет.

В интерфейсе доступны **Запуск / Пауза / 1 тик / Сброс**, управление скоростью,
seed, длиной эксперимента, тиком шока, долей отмены BUY-заявок и объёмом стресс-продажи.
Справа меняется реальный **внутри модели** лимитный стакан, в центре показываются
синтетические свечи OHLCV на основе исполненных виртуальных сделок; видны активность
четырёх правил поведения агентов и лента исполнений. `SIMULATED` не убирается из UI.

- `NOISE` (50% идентификаторов) — случайные лимитные и рыночные заявки;
- `MAKER` (20%) — пассивно добавляют объём в стакан;
- `TREND` (20%) — реагируют на изменение последней цены;
- `REVERSION` (10%) — реагируют против последнего движения.

Всего **1000 идентификаторов**, но **6 действий в тик по умолчанию**, не 1000 сделок на тик.
В v0.3 размер заявок ограничен свободными виртуальными средствами; мотивы остаются упрощёнными.

В версии 0.2 эксперимент LQ-001 проводится внутри адаптивного рынка: на выбранном
тике обе конфигурации исполняют одинаковую принудительную продажу. При включённом
шоке перед продажей отменяется часть ближайшей BUY-ликвидности. Поведение агентов
после шока может расходиться; для строго парного теста с неизменной лентой событий
сохранён отдельно CLI из v0.1 (`python -m market_lab`).

**Безопасность:** HTTP существует исключительно для управления моделью в локальном
браузере на `127.0.0.1`. Сервер не выполняет исходящих сетевых запросов,
не подключается к биржам, не импортирует Kairos AGI и не хранит API-ключи.
Состояние симуляции находится только в памяти и теряется при перезапуске сервера.

## Быстрый запуск

Требуется Python 3.10+; внешние зависимости не нужны. Из корня репозитория:

```bash
python -m market_lab
python -m unittest discover -s tests -v
```

На Windows можно использовать `py -3.12 -m market_lab` и `py -3.12 -m unittest discover -s tests -v`.

После запуска в `artifacts/lq001/` появятся:

- `results.json` — параметры, входной hash, результаты двух сценариев;
- `timeseries.csv` — ряд цен, стакана, объёмов;
- `report.html` — автономная визуализация, открывается без сервера и интернета.

Пример параметров:

```bash
python -m market_lab --seed 42 --ticks 150 --shock-tick 80 \
    --cancel-percent 85 --cancel-levels 8 --sell-qty 26
```

## Границы версии 0.1 (CLI, сохранена без изменений)

- Ценовой тик = `0.1 VCU`; объёмы = целое число виртуальных единиц; котировки в целых тиках без округления денежного ledger.
- В стакане реализованы пассивные лимитные заявки, ценово-временной приоритет, рыночные ордера, частичное исполнение, отмена ликвидности, проверка сохранения количества виртуальных единиц.
- 1 000 агентских **идентификаторов** доступны генератору; каждый обычный тик создаёт одно случайное действие, а не 1 000 заявок. Агентский капитал и балансы пока не моделируются.
- Для контрольного сравнения действия агентов генерируются **до запуска сценариев** и воспроизводятся без адаптации к новой цене. Поэтому это тест механики стакана, **не** реалистичная поведенческая модель кризиса.
- Комиссии, реальные биржевые ограничения, взаимодействие с реальными счетами, LLM, свечи OHLCV и сетевой UI пока **не** реализованы. Последующие этапы изложены в `docs/TECHNICAL_SPEC.md`.

## Безопасность

- Нет клиента биржи, HTTP, WebSocket, сетевых функций, SDK или работы с секретами.
- Нельзя отправить ордер на реальную биржу: никаких путей исполнения на внешней площадке нет.
- Нет зависимостей или импортов из `Kairos_AGI` / `kairos_next`.
- Режим данных всегда `SIMULATED`; программа записывает только локальные файлы результатов.

Лицензию можно добавить после отдельного решения владельца. Публичность репозитория сама по себе не означает предоставления прав на использование кода третьими лицами.
